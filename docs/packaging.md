# Packaging — DEB and Homebrew

This document covers how to build, install, and publish vellum as a native
system package on Debian/Ubuntu (`.deb`) and macOS/Linux via Homebrew.

---

## DEB Package (Debian / Ubuntu)

### What gets built

`cargo-deb` reads `[package.metadata.deb]` in `Cargo.toml` and produces a
standard `.deb` archive containing:

| Path | Content |
|------|---------|
| `/usr/bin/vellum` | Release binary (stripped) |
| `/usr/share/doc/vellum/README.md` | Upstream README |

### Build locally

```bash
# 1. Install cargo-deb (one-time)
cargo install cargo-deb --locked

# 2. Build the .deb
cargo deb

# Output: target/debian/vellum_<version>_<arch>.deb
```

### Install the package

```bash
sudo dpkg -i target/debian/vellum_0.6.0_amd64.deb
# or
sudo apt install ./target/debian/vellum_0.6.0_amd64.deb   # resolves deps
```

### Uninstall

```bash
sudo apt remove vellum
```

### CI / GitHub Actions

The `deb-build` workflow (`.github/workflows/deb-build.yml`) triggers
automatically on any semver tag push (`0.*.*`, `0.*.*-rc*`).

It:
1. Checks out the repo with full history + tags
2. Installs `cargo-deb` via `cargo install`
3. Runs `cargo deb` → produces `target/debian/*.deb`
4. Uploads the `.deb` as a workflow artifact named `deb-packages`
5. Uploads the `.deb` to the GitHub release (via `upload_to_release: auto`)

To trigger manually: **Actions → deb-build → Run workflow**.

To attach the `.deb` to an existing release (backfill):

```bash
gh workflow run deb-build.yml --repo nikolareljin/vellum --ref main \
  --field release_tag=0.6.0
```

### Package metadata

Configured in `Cargo.toml` under `[package.metadata.deb]`:

```toml
[package.metadata.deb]
name            = "vellum"
maintainer      = "Nik Reljin <nikola.reljin@gmail.com>"
copyright       = "2026, Nik Reljin"
license-file    = ["LICENSE", "4"]
extended-description = "..."
depends         = "$auto"          # auto-detect shared-library deps
section         = "utils"
priority        = "optional"
assets          = [
  ["target/release/vellum", "usr/bin/vellum", "755"],
  ["README.md",             "usr/share/doc/vellum/README.md", "644"],
]
```

`$auto` tells `cargo-deb` to run `dpkg-shlibdeps` and fill in the
`shlibs:Depends` field automatically.

### `debian/` directory

A minimal `debian/` tree is also present for use with the standard
`dpkg-buildpackage` toolchain (e.g., PPA submissions, `sbuild` chroots):

```
debian/
  changelog    # Debian-format changelog (dch-compatible)
  control      # Source + binary package metadata
  copyright    # DEP-5 machine-readable copyright
  compat       # debhelper compat level (13)
  rules        # Build rules (overrides dh_auto_build → cargo build --release)
```

To build with `dpkg-buildpackage` instead of `cargo-deb`:

```bash
# Requires: debhelper, devscripts, rustc, cargo, libssl-dev
sudo apt install debhelper devscripts rustc cargo libssl-dev
dpkg-buildpackage -us -uc
# .deb lands in ../
```

## Homebrew Formula (macOS / Linux)

### What gets built

The `release-tarballs` workflow builds pre-compiled binary tarballs for
macOS (arm64 and x86_64) and Linux (x86_64), then updates the Homebrew
formula in the tap with the correct SHA-256 checksums. Users install a
native binary — no Rust compiler required.

### Install

```bash
brew tap nikolareljin/tap
brew install vellum
```

Upgrade / uninstall:

```bash
brew upgrade vellum
brew uninstall vellum
```

### Formula structure

The formula lives in the [`nikolareljin/homebrew-tap`](https://github.com/nikolareljin/homebrew-tap)
repo at `Formula/vellum.rb`. It is auto-generated by CI on every release —
do not edit it by hand.

```ruby
class Vellum < Formula
  desc    "Rich Markdown viewer for the terminal"
  homepage "https://github.com/nikolareljin/vellum"
  version "<version>"
  license "MIT"
  tag = "<tag>"

  on_macos do
    if Hardware::CPU.arm?
      url "https://github.com/nikolareljin/vellum/releases/download/#{tag}/vellum-#{tag}-macos-arm64.tar.gz"
      sha256 "<sha256>"
    else
      url "https://github.com/nikolareljin/vellum/releases/download/#{tag}/vellum-#{tag}-macos-x86_64.tar.gz"
      sha256 "<sha256>"
    end
  end

  on_linux do
    url "https://github.com/nikolareljin/vellum/releases/download/#{tag}/vellum-#{tag}-linux-x86_64.tar.gz"
    sha256 "<sha256>"
  end

  def install
    bin.install "vellum"
  end

  test do
    assert_match "vellum", shell_output("#{bin}/vellum --help")
  end
end
```

### CI / GitHub Actions

The `release-tarballs` workflow (`.github/workflows/release-tarballs.yml`)
triggers on semver tag pushes via `rust-release-tarballs@production` from
[ci-helpers](https://github.com/nikolareljin/ci-helpers).

It:
1. Builds binary tarballs for macOS arm64, macOS x86_64, and Linux x86_64
2. Uploads tarballs to the GitHub release
3. Computes SHA-256 for each tarball
4. Updates `Formula/vellum.rb` in the tap repo and pushes the change

Required secret: `HOMEBREW_TAP_GITHUB_TOKEN` — a PAT with `contents:write`
on `nikolareljin/homebrew-tap`.

To trigger manually (backfill):

```bash
gh workflow run release-tarballs.yml --repo nikolareljin/vellum --ref main \
  --field release_tag=0.6.0
```

## Release checklist

When cutting a new release:

1. Bump `version` in `Cargo.toml`
2. Update `VERSION` file to match
3. Add entry to `CHANGELOG.md`
4. Update `debian/changelog` (use `dch -v <version>-1` or edit manually)
5. Commit: `git commit -m "chore: bump to <version>"`
6. Tag: `git tag <version>` (no `v` prefix — see tagging convention)
7. Push tag: `git push origin <version>`
8. CI triggers: `rust.yml`, `rust-scan.yml`, `release.yml`, `release-tarballs.yml`, `deb-build.yml`
