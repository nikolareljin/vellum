Troubleshooting

The common problems, what causes them and what to change. If yours is not here, open an issue with your terminal, your OS and the vellum version.

Images

Images look blocky

The terminal did not answer for Kitty, Sixel or iTerm2 graphics, so vellum drew half-blocks. Use a terminal with one of those protocols (kitty, WezTerm, iTerm2, foot, or another with Sixel) for full resolution. Check that VELLUM_PROTOCOL=halfblocks is not set in your shell.

Images are missing or garbled inside tmux or screen

Multiplexers often do not pass graphics through. Set VELLUM_PROTOCOL=halfblocks for a reliable picture, or run vellum outside the multiplexer.

An image shows [remote image not loaded: host]

This is the default: vellum makes no network requests unless you ask. Run with --remote-images or set VELLUM_REMOTE_IMAGES=1. If it still does not load, check that:

  • the URL is https; plain http is refused, also after a redirect;
  • the host does not resolve to a private, loopback or link-local address;
  • the image is under 20 MiB and loads within 10 seconds;
  • VELLUM_NO_REMOTE_IMAGES is not set, since it overrides the flag.

A video shows no thumbnail

Install ffmpeg and make sure it is on your PATH.

Copying code

Nothing happens when I press y

Select a block first: c, ] or a click. y and Enter only copy when a block is selected and its header shows [ y: copy ]. The status bar then reports the method used, or the error.

Copy says it worked over SSH, but my clipboard is empty

Over SSH vellum always copies with OSC 52, which your local terminal must accept.

  • kitty, WezTerm, iTerm2, foot and Windows Terminal accept it. Some have a setting that blocks clipboard writes; check it is allowed.
  • xterm needs allowWindowOps enabled.
  • Inside tmux, add set -g set-clipboard on or set -g allow-passthrough on to ~/.tmux.conf and reload it. vellum sends a form that works with either.
  • GNU screen and some older terminals drop OSC 52. There is no workaround from vellum's side.

The block is too large for OSC 52

OSC 52 carries about 73 KB of code. vellum refuses larger blocks rather than let the terminal cut them short. Locally, install a clipboard tool (wl-copy, xclip or xsel) so OSC 52 is not needed. Over SSH, copy from the file on the remote host instead.

"no clipboard available ... this terminal ignores OSC 52"

vellum found no clipboard tool and no system clipboard, and your terminal (GNOME Terminal, xfce4-terminal and other VTE terminals) drops OSC 52. Install xclip (X11) or wl-clipboard (Wayland), or use a terminal that accepts OSC 52 (kitty, WezTerm, foot, Alacritty). Running inside tmux only fills tmux's own paste buffer, because the VTE terminal around it still drops the copy.

Copy on Linux uses OSC 52 although xclip is installed

vellum calls xclip and xsel only when DISPLAY is set, and wl-copy only when WAYLAND_DISPLAY is set. From a plain console or a session without those variables it falls back to the system clipboard, then to OSC 52.

Display and keys

Colours look wrong

vellum uses 24-bit colour. Make sure your terminal supports truecolor; inside tmux, enable it with set -ga terminal-overrides ",*:Tc" or the RGB feature.

Alt+Left does nothing

History only exists after you follow a link to another local Markdown file. Some terminals and macOS keyboard settings also take Alt+Left for themselves; check that the terminal sends it to the application.

A web link does not open

vellum opens http, https and mailto links with xdg-open on Linux and open on macOS. Install xdg-utils on a minimal Linux system. On native Windows web links are not opened.

The e key opens the wrong program

Code view runs $EDITOR, then $VISUAL, then bat, less or cat. Set EDITOR to the program you want.

My custom theme is not found

--theme mine reads ~/.config/vellum/themes/mine.json, or $XDG_CONFIG_HOME/vellum/themes/mine.json when XDG_CONFIG_HOME is set to an absolute path. The file must be valid JSON. Missing fields are fine.

Text I can see in another viewer is missing

vellum strips invisible characters: escape sequences, carriage returns, bidi marks and zero-width characters. That is deliberate, so a file cannot hide text or control your terminal. Open the file with e to see the raw bytes.

Report a problem

  • Source: the code is the authoritative answer to "what does this key do".
  • Changelog: what changed in each release.
